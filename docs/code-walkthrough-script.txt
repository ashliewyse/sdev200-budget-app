01-introduction — Working budgeting app
This is a computer-narrated code walkthrough of Ashlie Wyse's SDEV two hundred final project. Budget Planner is a Java application with a J S P browser interface. It continues the fifty, thirty, twenty method chosen in Module Three. This demonstration uses fictional local profiles and example transactions. The planner does not connect to any bank.

02-demonstration — Monthly targets and entries
For Demo Ashlie, October's take-home income is three thousand dollars. The app calculates fifteen hundred dollars for needs, nine hundred for wants, and six hundred for goals. The rent example is fifty dollars above the needs target, so the card shows that difference. Wants spending is one hundred dollars. A two hundred dollar savings contribution leaves four hundred to the goals target. The entry form records a date, description, category, and amount. Entries can be deleted to correct a mistake. Switching a month or profile opens separate saved records.

03-calculation — Interface enum and calculation
The Budget Method interface defines a calculate operation. Fifty Thirty Twenty Method implements that interface, which satisfies the interface requirement and separates the budgeting rule from the web layer. Budget Category is the required enum, with needs, wants, and goals values. The calculation uses Big Decimal instead of binary floating point for currency. Needs and wants are rounded to two decimal places. Goals receives the remaining cents, so the targets always add up to the original income, even for small or uneven amounts. Invalid negative income and fractions of a cent are rejected.

04-domain — Data classes and application service
The project contains more than five ordinary Java classes. User Profile identifies a local person. Transaction stores one dated expense or goals contribution. Monthly Budget combines a profile identifier, a calendar month, income, and an immutable copy of its entries. Constructors validate records, including their dates and amounts. Budget Service coordinates changes and calculates dashboard summaries. Its synchronized operations prevent two requests in this running application from losing each other's updates. Category Summary and Budget Summary carry the results to the page, keeping the calculation and storage work out of the J S P.

05-storage — Separate persistent user data
File Budget Repository implements local persistence. Profile metadata is stored in profiles dot J S O N. Each generated profile identifier has a directory containing a separate file for each month. Display names never become storage paths. Loading checks that a budget belongs to the requested profile and month. A missing month starts empty, but an invalid existing file produces an error rather than silently resetting data. Saving first writes a completed temporary file beside the destination and then replaces the destination, using an atomic move where supported. Closing and reopening the app retains these files. Profiles separate data, but are not password protected.

06-web — JSP forms and controller
Budget Controller handles browser requests. It takes the active profile from the browser session rather than trusting a posted profile identifier as a file owner. The controller passes validated changes to the service and supplies page models. Successful form submissions redirect to a display request, so refreshing the page does not repeat the same change. A session token guards state-changing forms. The dashboard is an actual J S P, using J S T L to display values. User text is escaped, so a description cannot turn into executable markup. Validation errors preserve input, and storage errors display the unsaved values without reporting a successful save.

07-verification — Tests help and delivery
Automated tests check the currency rules, invalid input, monthly totals, separate profiles, saving and reloading, deletion, concurrent updates, and file error handling. Other tests start the real web server to check J S P rendering, Unicode text, and escaped markup. The packaged W A R is also checked in the browser, including an application restart. The Help page explains normal use, and the GitHub read me provides build and run instructions, storage details, and a class map. The finished source is available in the S D E V two hundred budget app repository. This video is a separate computer-narrated deliverable.
